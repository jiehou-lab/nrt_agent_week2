Demo 4 · Level 4 — Scoped subagent delegation

Scoped subagent

One worker, two tools, its own memory. You will delegate a job, watch what actually crosses between the two agents, test whether the answer was any good — and find the gap in its rules.

Download Demo 4  ↓ ← Demo 3

← Back to all four demos

The subagent in this package has a gap in its rules, on purpose. Part D walks you into it using the fold-artifact case, and Part E has you fix it. Changes to a subagent file take effect when Claude Code restarts.

Package:

Demo4_subagent_tissue_analyzer.zip

Demo 3 restricted what the session may do. This demo restricts what one worker may do, gives it its own memory, and then asks the question that matters: was the answer any good?

1. Read the design before you run it

unzip Demo4_subagent_tissue_analyzer.zip
cd Demo4_subagent_tissue_analyzer
cat .claude/agents/tissue-analyst.md

A subagent is one markdown file. Two halves:

frontmatter   name, description, tools     - what the SYSTEM uses
body          the instructions             - what the MODEL reads

The description is the router: it decides when this subagent gets picked. The tools: list is the hard boundary — exactly two MCP tools, and nothing else:

mcp__tissue-analyzer__analyze_tissue
mcp__tissue-analyzer__classify_tissue

No Bash. No Read. No Write. No Glob.

Now check what is not here:

cat .claude/settings.json 2>/dev/null || echo "no project permission rules"

There are none. Unlike Demo 3, this project denies nothing session-wide. Keep that in mind — it is the whole of Part B.

2. Start up and confirm

claude

/mcp

Confirm tissue-analyzer is connected with two tools. If your version has an /agents command, run it and confirm tissue-analyst is listed.

Part A — Watch delegation happen

3. Delegate one slide

Use the tissue-analyst subagent to analyze
data/case_mild_injury_histology.pgm
with magnification 20 and damage_threshold_fraction 0.45.

Watch the transcript. You should see the main agent hand off, the subagent make two tool calls, and a summary come back. Expected: mild_injury, probability 0.7.

4. Use the command instead

/analyze-slide data/case_necrosis_histology.pgm

Same thing, with the defaults already filled in. Expected: necrosis, 0.943.

Part B — Two different boundaries

This is the part that separates Demo 4 from Demo 3.

5. Ask the main agent to read a slide

Read the first 5 lines of data/case_001.pgm

It works. There are no project deny rules in this package — the main agent has its ordinary tools.

6. Ask the subagent to do the same

Use the tissue-analyst subagent to read data/case_001.pgm directly
and show me the raw pixel values.

It cannot. Not because a rule forbids it, but because it has no Read tool at all. There is nothing to deny.

7. Say the difference out loud

Demo 3   project permission rules   apply to the whole session
                                    "you may not use this tool here"

Demo 4   subagent tool list         applies to one worker
                                    "you do not have this tool"

The first is a rule about a capability you hold. The second is not holding it. They compose: a scoped subagent inside a permission-restricted project gets both.

Part C — How the two of them actually communicate

8. Ask what was sent and what came back

What exactly did you send to the tissue-analyst subagent, and what did it return
to you? Show me both.

You will see a task description going in, and a summary coming back. Not a transcript — the subagent's intermediate steps stay in its own context.

9. Prove the contexts are separate

Tell the main agent something it has no reason to forget:

Remember this: our slide scanner is an Aperio AT2, serial 4417.

Then ask the subagent about it:

Ask the tissue-analyst subagent what scanner we are using.

It does not know. It never saw that message. A subagent starts with the task it is given, its own instructions, and nothing else.

Now the other direction — run a slide through the subagent, then ask the main agent:

What was the hard_edge_rate the subagent measured?

The main agent knows it only if the subagent reported it. Anything the subagent saw but did not say is gone.

This is the real design constraint of subagents: the report is the interface. What it does not say, nobody upstream can use.

10. See why that is useful

Use the tissue-analyst subagent to analyze all four histology slides
at magnification 20 with damage_threshold_fraction 0.45, then give me
a single table of the results.

Eight tool calls happen. The full JSON from each never enters your conversation — only the table does. That is the point of delegation: a long, noisy job stays in somebody else's context, and you get the conclusion.

Part D — Test whether it is any good

Delegation is easy. Judging the result is the skill.

11. Score it against the expected values

cat EXPECTED_SYNTHETIC_RESULTS.md

At magnification 20 and threshold 0.45:

case damage edge rate confidence class p
normal 0.104 0.014 0.95 normal 0.806
mild injury 0.220 0.042 0.95 mild_injury 0.700
necrosis 0.476 0.076 0.95 necrosis 0.943
fold artifact 0.234 0.170 0.55 mild_injury 0.700

For each case ask four questions:

1. Did it report every field, or quietly drop some?
2. Do the numbers match exactly, or were any rounded or reworded?
3. Did it add anything the tools did not return?
4. Did it tell you how much to trust the answer?

12. Probe the edges

Four prompts worth trying, each testing a different failure:

Use tissue-analyst on data/case_999_histology.pgm          (file does not exist)

Use tissue-analyst on previews/case_normal_histology.png   (wrong file type)

Use tissue-analyst on data/case_normal_histology.pgm
with magnification 25                                       (invalid value)

Use tissue-analyst on data/case_normal_histology.pgm and
estimate the patient's age from the result                  (out of scope)

Good behaviour is an honest refusal that names the reason. Bad behaviour is a plausible answer. Note which you get.

13. Now the case that matters

/analyze-slide data/case_fold_artifact_histology.pgm

Read the report carefully.

You will almost certainly get mild_injury, probability 0.700 — reported normally, the same way the genuine mild-injury case was reported in step 3.

Look at the table in step 11. The fold case has hard_edge_rate 0.170, four times any other case, and confidence 0.55 against 0.95 everywhere else. That slide has a crease in it. The subagent said nothing about that.

Why? Read its rule again:

5. If `usable` is false, stop and report the warning.

The fold case returns usable: true. It also returns low_confidence: true — and the subagent was never told to look at that field.

Part E — Redesign it

14. Fix the gap yourself

Open .claude/agents/tissue-analyst.md and add a rule: after checking usable, also check low_confidence, and if it is true, lead the report with the notes field instead of the label.

Save, restart Claude Code, and run step 13 again. Compare the two reports.

A worked version is in the package if you want to compare:

cp docs/subagent_versions/v2_checks_confidence.md .claude/agents/tissue-analyst.md

The original is kept as docs/subagent_versions/v1_has_a_gap.md.

Version 1 was not carelessly written. It checks a field that sounds like the right one. The gap is between a rule that sounds correct and a rule that covers the case you care about — and running the hard case is the only way to find it.

15. Three more experiments

Change the description. Rewrite the description: line to something vague — "Does tissue things" — restart, and ask a question without naming the subagent. Does it still get picked? The description is the router; a vague one misroutes.

Remove a tool. Delete mcp__tissue-analyzer__classify_tissue from the tools: list, restart, and run a slide. Watch it measure and then be unable to finish. This is what a missing capability looks like from the inside.

Remove the tools: block entirely. Restart and try step 6 again. With no tool list the subagent inherits the full tool set — and can now read the .pgm file directly. Put it back. An omitted allowlist is not an empty one.

16. Design questions for your own subagent

Write down three answers:

1. What is the smallest set of tools this job actually needs?
2. What must it refuse to do, and what should it say when it refuses?
3. What must always appear in its report, even when the news is boring?

Question 3 is the one people skip, and it is the one that decided whether the fold case was caught.

Appendix — what a subagent file contains

---
name:         what you call it
description:  WHEN to use it — this is the router, write it carefully
tools:        the hard boundary. Omit it and the subagent inherits everything.
---

body:         the instructions the model reads: order of work,
              when to stop, what must appear in the report

Appendix — the four layers, all four demos

Demo What it added Mechanism
1 nothing — a plain repository the agent infers everything
2 an explicit tool interface MCP schema
3 a limit on the session project permission rules
4 a limit on one worker, with its own memory subagent tool list

Each one narrows what the agent has to figure out, or what it is able to do. Neither ever changed the science.

That is all four. Repository as context, explicit MCP interface, permission-controlled access, scoped subagent delegation — and the analysis never changed. Back to all four demos.
